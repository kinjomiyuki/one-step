# アプリをマネタイズする型(OneStep で実際に通った流れ)

## 新しいアプリで使うとき(最初に)

課金のコード(Function、画面の部品、設定スクリプト、テスト、法務の文面)は、OneStep のリポジトリ(https://github.com/kinjomiyuki/one-step、手元は `C:\dev\one-step`)にある。この文書のファイル名は、そのリポジトリのものなので、新しいアプリには、まだ、ない。

1. 新しいアプリのフォルダに、課金のファイルをコピーする(OneStep のフォルダで実行する)。

```
cd C:\dev\one-step
git fetch origin; git reset --hard origin/main
node scripts/export-monetization.mjs <新しいアプリのフォルダ>
```

   AI の回答と費用の上限が要らないときは、`--no-ai` を付ける。すでにあるファイルは、上書きしない。
2. コピーしたあとの、手で直すところは、コピーされた `docs/monetization-template.md` に従う(設定ファイル、名前・価格・サイト ID・無料の範囲、法務の文面、画面へのつなぎ込み)。
3. そのあとは、下の「手順(この順番)」を進める。

OneStep のフォルダが、手元にないときは、先に、リポジトリを `git clone` する。


構成: フロントは React + Vite、サーバーは Netlify Functions。Stripe は SDK を使わず fetch で呼ぶ。購入の確認は、Stripe に確かめ直す署名付きトークン(データベースなし)。保存が必要なものは Netlify Blobs。メールは Resend。詳細は `docs/premium-setup.md`、実装は `netlify/functions/`、`netlify/lib/`、`scripts/`。

## 進め方の原則

- **スイッチを先に作る。** 有料機能は、環境変数 `PREMIUM_ENABLED` が `true` のときだけ有効にする。未設定なら全員が無料。準備中も、公開中のサイトが壊れない。
- **テストと本番は、別の環境。** 価格・ポータル・Webhook・鍵が、モードごとに別。本番に切り替えるときは、すべて、本番の鍵で作り直す。
- **無料のレベルを残す。** 無料で価値が伝わる範囲を残してから、有料に誘導する(`src/utils/plans.js` の `FREE_LEVELS`)。
- **AI の費用に上限を置く。** 1日の費用の上限(`CHAT_DAILY_BUDGET_YEN`)、短い履歴、短い回答、考える量を抑える。有料機能の AI 回答は、サーバー側でトークンを確認する。

## 手順(この順番)

1. **設計を決める(質問する)**: 無料の範囲、価格(税込か)、月額か買い切りか、購入の復元方法(メールのリンク)、1日の AI 費用の上限。
2. **実装**: checkout / entitlement / portal / login-link / stripe-webhook / config の Function、トークンの署名、画面(Paywall、ロックされたレベル、プランの管理)、利用規約・プライバシーポリシー・特定商取引法の表記。事業者情報(`src/data/business.js`)が空のうちは、法務リンクを出さない。
3. **テストを書く**: Stripe とメールは、`fetch` を模擬して確かめる。Netlify Blobs は、保存先を差し替える。トークン、署名、失効、上限、設定スクリプトを、それぞれ。
4. **Stripe(テストモード)**: `node scripts/setup-stripe.mjs --netlify --entitlement --webhook` で、商品・価格・ポータル・Webhook を作り、Netlify に登録する。`--entitlement` は初回だけ。
5. **Resend**: API キーと送信元(`MAIL_FROM`)。独自ドメインがないと、登録者本人にしか送れない。購入者に送るには、ドメインの認証が必要。
6. **確認**: `node scripts/check-setup.mjs` で、Stripe と Netlify の環境変数の状態を一覧で確認する(鍵は表示しない)。
7. **購入のテスト**: テストカード `4242 4242 4242 4242` で、購入 → 中級が開く → プランの管理 → 解約 を試す。テスト中だけ `PREMIUM_ENABLED=true`、終わったら戻す(実際の利用者が、払えないため)。
8. **本番**: Stripe の本番の有効化(本人確認・口座)→ 本番の鍵で `--netlify --webhook --live`(`--entitlement` は付けない)→ `check-setup` で「モード: 本番」を確認 → 法務を確認 → `PREMIUM_ENABLED=true` → デプロイ → 本物のカードで最初の購入を試す。

## つまずいた点(先回りして防ぐ)

- **鍵はチャットに貼らせない。** 鍵は、本人の PowerShell にだけ入力する。説明用の見本(`sk_test_xxxxxxxx`)を、消さずに残して、壊れた鍵になりやすい。「ここは鍵だけ」と書く。結果を貼ってもらうときは、鍵が混ざっていないか確認してから、と添える。スクリプトの出力に、鍵や秘密の値を出さない作りにする(エラー表示にも)。
- **鍵の種類**: 権限を絞って作ると `rk_`(制限付きキー)になる。`sk_` だけを受け付ける検査にしない。権限は「重要な操作を除くフルアクセス」。「フルアクセス」は選ばせない。
- **Netlify の secret**: `--secret` には `--context production` が必要。適用先を指定せずに一覧を取ると、本番だけの変数が、未登録に見える(確認スクリプトでも、`--context production` で取る)。
- **環境変数を変えたら、再デプロイ。** 反映されるまで、サイトは変わらない。
- **デプロイは、必ず正しいフォルダとサイトで。** ホームフォルダで `netlify deploy --prod` を実行すると、別のサイトに、フォルダ全体を公開しようとする。次の1行にまとめて、フォルダを移ってから、サイトの ID を指定して実行する。

```
if (Test-Path C:\dev\one-step\netlify.toml) { cd C:\dev\one-step; git fetch origin; git reset --hard origin/main; npx netlify deploy --prod --site <サイトのID> }
```

- **PowerShell に、複数のコマンドを一度に貼ると、くっつく。** 1行ずつ貼らせる。アドレス(URL)を PowerShell に貼らせない。確認は `(Invoke-WebRequest -UseBasicParsing <URL>).Content`。
- **Stripe の環境が、複数ある。** 「アプリサンドボックス」「テスト環境」「本番」は別。鍵を取った画面の左上のアカウント名を、確認させる。価格 ID の途中の文字列(アカウント固有)が、前回と違えば、別の環境。
- **Stripe の接続(MCP)が、読み取り専用のことがある。** 書き込みは、「Forbidden」で拒否される。その場合は、設定スクリプトを、本人に実行してもらう。
- **解約の反映**: Webhook で失効を記録する。Stripe に確かめ直す作りにして、通知の順番が前後しても、結果が正しくなるようにする。記録を読めないときは、支払い中の人を締め出さない。
- **限界(正直に伝える)**: 有料の内容が、画面のプログラムに含まれている場合、画面の制限は、技術のある人には破れる。守りたいなら、内容を、サーバーから配信する作りにする。

## 売り始める前の最終確認

- 事業者情報(5項目)と返金の方針を、本人が決めて記入した。住所・電話番号の公開方法は、本人の判断(消費者庁の案内か専門家で確認)。
- 法務の文面は、案であることを伝え、本人に確認してもらった。
- Stripe の事業の URL が、実際のサイトの URL と、一致している。
- 本番で、最初の購入を、本人が、本物のカードで試した(サブスクの状態・金額・Webhook の通知が「200」)。
- 問題があれば、`PREMIUM_ENABLED` を `false` にして、再デプロイすれば、すぐに止められる。

## 進行中の振る舞い

- 本人が、ブラウザや PowerShell の操作に慣れていない前提で、手順を、1行ずつ、短く書く。
- 自分にできること(コード、テスト、マージ、環境変数の設定)と、本人にしかできないこと(本人確認、鍵、デプロイ、法務の判断)を、はっきり分ける。できないことを、できたように言わない。確認できていないことは、確認できていないと言う。
- 外部へ影響することは、実行する前に、確認する(有料のオン、本番の鍵、削除)。
